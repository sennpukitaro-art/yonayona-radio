# 同意された会話を運営が確認する

追加料金のあるデータベースや公開管理画面は使わない。MC2人が任意で同意した番組に限り、会話を暗号化してサーバーのappログへ出力し、運営が書き出しを手元で復号する。

## 利用者への表示

- 保存が有効なサービスでは、参加ボタンの前に未選択の同意欄を表示する。同意しなくても参加できる。
- 招待作成・招待参加・ランダム待機を開始するときの選択を使う。番組が始まる時点でMC2人とも同意している場合だけ保存する。
- 保存中かどうかを番組内に表示する。MCは「この番組の保存を止める」で以降の保存を番組全体で止められる。保存済み発言の削除や途中からの保存再開ではない。
- 保存対象はMCの本文・お題・日時・番組単位のランダムな識別子・MC A/Bの区別。ニックネーム・接続ID・流入元・招待トークン・リスナーコメントは含めない。ただし本文そのものに書かれた情報は保存される。
- 通常の参加者が放送中の会話を読める仕様は従来どおり。保存の同意は、運営による終了後の閲覧のためのもの。

## 初期状態と反映

`RADIO_ARCHIVE_KEY` が未設定なら保存しない。設定する場合は32バイトのランダム鍵を64桁の16進文字列で指定する。不正な値は本文や鍵を出さず起動エラーにする。鍵はブラウザーへ送らず、リポジトリへ登録しない。

**GitHubへのコード反映と会話保存の有効化は別の操作。鍵未設定では保存しない。鍵の設定前に同意画面・保存状態表示と、ワークスペースの実際のログ保持期間を確認する。**

更新時は、運営手順の利用中更新を避ける確認を行い、同意欄と保存状態表示を含む一式で反映する。保存だけを先に有効化しない。

## 鍵の準備（有効化するときに運営の端末で）

リポジトリ外の非公開フォルダーで実行する。既存ファイルには上書きせず、鍵を標準出力へ出さない。

```sh
node -e "require('node:fs').writeFileSync('conversation.key',require('node:crypto').randomBytes(32).toString('hex'),{flag:'wx',mode:0o600})"
```

同じ鍵をRenderの非公開環境変数 `RADIO_ARCHIVE_KEY` に設定する。鍵を紛失したログは復号できない。鍵を変更した場合は古い鍵も安全に保持し、鍵ごとにログを分けて読む。

## 運営が読む手順

1. Renderのappログで `radio_transcript` を絞り込み、期間を指定して書き出す。ページ取得の残りがあれば取得する。タイムスタンプ付きの1行JSONに対応。
2. 運営の端末で次を実行する。鍵の値自体を引数に書かない。

```sh
node scripts/read_conversations.js --key-file /private/conversation.key /private/export.log /private/conversations.html
```

3. 出力HTMLをブラウザーで開く。外部通信・JavaScriptなし。本文をHTMLとして実行せず文字として表示する。出力は所有者のみ読み書き可能（対応するOSで0600）に作成し、既存ファイルを上書きしない。

HTMLは復号済みの本文を含む非公開資料。公開サイト・公開リポジトリや一般公開のファイル共有先には置かない。確認後は運営が削除する。

## 保持期間と限界

- サーバー側ではRenderのログ保持期間に依存する。独自の7日削除などは実装していない。Renderの現在の公式案内ではHobbyワークスペースは7日、Proは14日、Scale/Enterpriseは30日。**このサービスが無料インスタンスであることだけではワークスペースプランを断定できないため、反映前に契約画面で確認する。** 利用画面には期間を断定せず「サーバーログの保持期間内」と表示する。
- ログ自体が欠ける、保持期間を過ぎる、取得範囲が途中、停止・再起動で終了イベントがない場合は完全な会話にならない。HTMLは開始・終了・連番がそろわなければ「取得は一部」と示す。そろっていても保存の対象外だった発言は含まない。
- 同じ書き出しの重複行は番組と連番でまとめる。異なる内容の同じ連番、鍵違い、改変・破損した暗号ログは失敗として扱い、本文をエラー出力しない。
- 本文はAES-256-GCMで暗号化する。ログサービスには暗号文が送られ、鍵を持つ運営は内容を読める。サーバーは送受信の際に本文を処理するため、エンドツーエンド暗号化ではない。
- 保存に同意されなかった番組、導入前の過去の会話は復元できない。これで一般利用者同士の会話か、別人か、ボットかまで自動証明できるわけではない。

参考：Render公式 https://render.com/docs/logging 、Node.js公式 https://nodejs.org/api/crypto.html
